## 2. A 级：正确性修复（建议全部做）

### A1 快捷入口补连接引导

**问题。** 1.2.1 新增的插件快捷图标打开的是无连接上下文的 tab：`ui/app.js boot()` 只在 `ctx.connection` 带凭据时自动连接，否则停在空白连接表单，宿主托管连接的用户必须重输 AK/SK 或去连接树重开。入口「能点、点了没用」。

**方案。**
1. `manifest.json` 的 `command.action.context` 增加 `{"source":"shortcut"}`——宿主 `executePluginCommand` 会把它合并进 workbench context（只保留 `workbenchId/restored/surface` 三个宿主保留字段，自定义字段透传）。
2. `ui/app.js`：`ctx.source === "shortcut"` 且无 `ctx.connection` 且 `connection/status` 未连接时，不直接显示连接表单，先渲染**引导面板**：
   - 列出本机已保存连接（`savedConns`，`ui/conn.js` 已有读取/回填逻辑），点选即回填表单；
   - 明示一行：「宿主托管的连接请从左侧连接树打开，凭据由宿主注入」；
   - 提供「手动输入」按钮进入现有表单。
3. `ui/i18n.js` 补中英文案；`ui/styles.css` 补面板样式。

**不做的事。** 不声明 `host.connections:read` 自己列宿主连接——该权限给的是脱敏摘要、无 Secret，插件拿不到凭据，列出来也连不上。`connection_targets: true` 只有 dock「+」菜单消费（`PluginBottomDock.vue`），tab 命令拿不到，不碰。

**涉及文件**：`manifest.json`、`ui/app.js`、`ui/i18n.js`、`ui/styles.css`、`tests/manifest.test.js`（断言 action.context）。
**验收**：快捷图标打开 → 见引导面板 → 点本机已保存连接即回填可连；无保存连接时看到两条路径提示；原「从连接树打开」路径行为不变。
**工作量**：1 人日。**风险**：低；注意引导面板不破坏现有 `boot()` 三个分支的先后语义。

### A2 排序/过滤「仅当前页」标注 + 扫描全量排序

**问题。** `ui/browse.js:286` 注释自认：`sortItems()` 只排已加载的 items，滚动触底加载下一页后重排。用户点「大小降序」看到的头一条只是**前 N 条里最大的**，不是全目录最大的。`ui/search.js:19` 的过滤同理（大小/时间/扩展名/正则均为客户端筛选）。百万级目录下是静默错误结果。

**方案（两层，可只做第一层）。**
1. **明示层（必做）**：排序激活或过滤条件生效时，路径栏计数追加「（仅当前已加载 N 条）」；过滤面板头部加同款提示。用户至少不再被骗。
2. **全量层**：排序表头与过滤面板各加「扫描全目录后排序/筛选」按钮，复用深度搜索（`ui/search.js`）的递归翻页引擎：游标、进度、可取消、上限 2 万（可配），扫完把结果灌进当前列表视图并按所选键排序。扫描期间禁用再次触发。

**涉及文件**：`ui/browse.js`、`ui/search.js`（抽出可复用的扫描函数）、`ui/i18n.js`、`ui/styles.css`。
**验收**：① 默认行为有明确标注；② 2 万内目录点「扫描全量」后，大小降序第一条确为全目录最大；③ 扫描可取消且取消后回退到已加载视图。
**工作量**：1.5 人日。**风险**：中低——扫描引擎已有，主要是状态机接线；注意扫描结果与实时分页视图的状态互斥，避免两套 items 混写。

## 3. B 级：高价值功能（建议排 1.5 版本）

### B1 传输任务中心 + 失败批量重试

**问题。** 进度浮窗（`#dlCard`）是一次性的。上传已有失败重试（`OB.shared.uploadRetryFiles` + 断点续传），但**批量下载/删除/移动失败只透出首错 + 计数**（`ui/batch.js:271`），失败清单不落地，用户无法「重试失败的 3 个」。

**方案。**
1. 统一任务记录：`{ id, type: upload|download|delete|move|copy, bucket, keys[], ok, failed[{key,error}], ts }`。
2. **落盘在 sidecar**（`DBX_PLUGIN_DATA_DIR/tasks.jsonl`，复用上传断点元数据的落盘路径管理），不放 `storage`——宿主限单 key 256KiB、总量 1MiB，任务清单会超。
3. UI：工具栏加「任务」入口，打开覆盖层显示任务列表（本次会话在前，历史按需加载），失败任务展示逐 key 错误 + 「重试失败项」（下载/上传复用断点，删除/移动类不提供重试——重复执行有副作用，只记录）。
4. 上传/下载的既有重试按钮并入该中心，逻辑收敛到一处。

**涉及文件**：`backend/`（新增 tasks 读写 RPC，纯文件操作）、`ui/transfer.js`、`ui/batch.js`、新增 `ui/tasks.js`、`ui/index.html`、`ui/i18n.js`、`ui/styles.css`。
**验收**：批量下载 10 个文件断网 3 个 → 任务中心可见 3 条失败及原因 → 恢复网络一键重试成功；重启插件后历史仍在；`tasks.jsonl` 超过上限时滚动截断不崩。
**工作量**：3~4 人日。**风险**：中——跨 sidecar/前端两态；删除类「只记录不重试」要在 UI 上写死，防误操作。

### B2 跨页/全量选择后批量操作

**问题。** `OB.state.sel` 只覆盖已加载行，`Ctrl+A` 选不到未加载对象。用户想「删当前目录下全部 .log」必须先滚到底加载完。
**说明**：深度搜索结果内已支持批量，所以缺口精确为「不输关键词、对整个前缀做全量批量」。

**方案。** 工具栏/表头加「全选（含未加载）」：递归列举当前 prefix 全部 key（复用 A2 抽出的扫描引擎，同一套上限/进度/取消），得到全 key 集合后直接进入现有批量流程（删除/下载/移动均以 key 列表为输入，天然兼容）。与 A2/B1 共用同一基建。

**涉及文件**：`ui/browse.js`、`ui/search.js`、`ui/batch.js`、`ui/i18n.js`。
**验收**：10 万对象目录「全选含未加载」→ 批量删除走服务端分块批量，进度/取消正常；上限截断时明示「仅选中前 N 条」。
**工作量**：2~3 人日。**风险**：中——超大结果集的内存（2 万 key 字符串约几 MB，可控）；确认弹窗必须展示真实总数。

### B3 列表行内图片缩略图（网格视图不在此期做）

**问题。** 浏览图片库只能逐个点开预览。
**方案。** 列表「类型」列内嵌 20px 缩略图：`renderVisible()`（虚拟化可见窗口钩子，`ui/browse.js:717`）触发懒加载，`objects/read` Range 读小图 → `Blob URL` → 行内 `<img>`；离开视口或换页即 `revokeObjectURL`（复用 `preview.js` 的释放逻辑）。LRU 上限约 200 张防内存。**不做网格视图**——需重写虚拟化，收益不成比例。
**涉及文件**：`ui/browse.js`、`ui/transfer.js`（或新增 `ui/thumb.js`）、`ui/i18n.js`。
**验收**：千张图片目录滚动流畅；内存不随滚动线性涨（DevTools 观察 Blob 数量收敛）；只读连接可用。
**工作量**：2~3 人日。**风险**：中——内存与请求节奏；必须限并发（复用 3 路并发的节流）。

### B4 目录占用/大小统计

**问题。** `objects/dir_info` 只统计对象数（上限 1000 + truncated），清理存储时最想知道「哪个目录占空间」。
**方案。** 后端 `objects/dir_size`：递归列举累计 size（复用 `DeletePrefix` 的流式分页模式），返回 `{ bytes, objects, truncated, topDirs[] }`（一级子目录占比，便于定位大户）；可取消（长任务走轮询或分段返回，v1 先用阻塞 + 硬上限 5 万对象 + 明示截断）。前端入口：目录右键「统计大小」，结果缓存到 `storage`（key=`size:{bucket}{prefix}`，量小放得下）。
**涉及文件**：`backend/driver*.go` 或 `rpc_objects.go`、`ui/browse.js`、`ui/i18n.js`。
**验收**：已知大小目录统计误差为零；截断时明示；取消立即生效。
**工作量**：3 人日。**风险**：中——大目录耗时长，必须硬上限 + 截断明示，避免「转圈到天荒地老」。

## 4. C 级：低成本高频（半天~1 天/项）

### C1 文件管理器快捷键补全
现状仅 `Ctrl+A / Ctrl+F / F3 / Shift连选 / Delete / F2`。补：`↑/↓` 移动选中（含 Shift 连选）、`Ctrl+C/V` 复制粘贴对象（粘贴=进入目标目录后确认执行，复用 `objects/copy`）、`空格` 快速预览当前行、`Enter` 进目录。全部走 `ui/browse.js` 现有键盘委托，注意输入框聚焦时不劫持。**验收**：纯键盘完成 浏览→预览→复制→粘贴 全流程。1 人日。

### C2 预览不支持时给「下载打开」入口
`preview.unsupported`（`ui/preview.js:917`）现在只有一句提示。补「下载到本机并打开」按钮（`objects/save` 已有流式落盘 + `app/pick_dir`）。只读连接同样可用。0.5 人日。

### C3 本机操作历史 / 误删追溯
删除不可撤销（i18n 已明示），至少留下痕迹：删除/移动/覆盖写之前把 key 清单追加到 sidecar `DBX_PLUGIN_DATA_DIR/history.jsonl`（滚动上限，如最近 5000 条），UI 提供「最近操作」查看 + 按时间过滤。不做恢复（无 versionId，承诺不了），只做追溯。1.5 人日。可与 B1 的落盘基建合并做。

### C4 常用路径书签 / 最近访问
深层目录每次从根点进去。工具栏加书签下拉 + 「添加当前路径」；另自动记最近 10 个访问位置。存 `storage`（几 KB）。`ui/browse.js` + `i18n.js`。1 人日。

### C5 批量生成分享链接
多选文件 → 逐个 `objects/presign`（已有，含失败回退）→ 汇总为「key\tURL」文本复制 / 导出 CSV；S3 侧 7 天上限沿用现有提示。注意批量上限（如 100/次）防滥用。1 人日。

## 5. 明确不做（及理由）

| 项 | 理由 |
|---|---|
| D1 目录双向同步 / diff | 对象存储无原生 rename/move，全靠 copy+delete，冲突、一致性、幂等是另一个产品级复杂度；用户可用「跨桶复制 + 批量删除」覆盖 80% 场景 |
| D2 硬啃 .ppt 二进制 / draco glTF / CAD 预览 | 授权不干净（专有水印引擎、MPL/LGPL 解码器），README 的授权边界是刻意决策 |
| D3 多标签分栏对比 | 宿主 tab 模型决定，插件侧无法开分栏；`openWorkbench` 多实例已够用 |
| D4 回收站 / 撤销删除 | 全仓无 versionId 支持（已 grep 确认），桶未开版本控制时承诺了也做不到；C3 的追溯是诚实降级 |
| D5 S3 在线改 ACL | minio-go v7 无 PutObjectAcl，README 已声明走控制台，除非换 SDK 否则无解 |

## 6. 基建：T0 测试补强（随 A/B 强制带上）

`tests/` 现有 3 个测试 + `manifest.test.js`，但批量操作的**取消 / 失败 / 恢复**路径零覆盖，而 B 级功能全部压在这些路径上。补：
1. `tests/batch_flow.test.js`：批量删除/下载的取消中断、失败清单、失败重试的纯函数逻辑抽测（把 batch.js 里的计划/汇总逻辑抽成可测纯函数）；

3. 后端 `go test`：`tasks.jsonl` 读写、`dir_size` 截断语义。
2 人日，**作为 A/B 级合入的门槛条件**。
